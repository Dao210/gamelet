# PRD：不可能仪器馆——六款新奇益智游戏

## 1. 项目概述

在 Gamelet 中新增一个共享世界观的六款益智游戏系列：**不可能仪器馆（The Cabinet of Impossible Instruments）**。

玩家扮演新任仪器校准员，依次修复六台违反直觉的实验仪器。六款游戏共享世界观、档案编号、视觉语言和进度系统，但核心操作与推理模型完全不同。项目优先追求“第一次见到这种玩法”的新奇感，而不是复刻数独、三消、华容道、Wordle、记忆翻牌或普通选择题。

每款游戏包括：

- 6–10 个固定教学/进阶关卡；
- 一个基于确定性随机种子的无限模式；
- 独立的局内计分、提示和失败恢复；
- 系列共享的仪器修复进度与成就陈列；
- 可复现并可分享的每日种子。

## 2. 产品目标

- 六款游戏的核心动作互不重复，且不复用当前 12 款游戏的主要玩法。
- 玩家在 30 秒内理解每款游戏的首个操作，在 2 分钟内遭遇第一次规则反转。
- 每款固定关卡完成后仍可通过无限模式持续游玩。
- 程序生成关卡必须在展示给玩家前经过可解性验证。
- 六款游戏共享进度、存储、随机数、结果页和可访问性基础设施。
- 移动端单手可完成主要操作；桌面端同时支持鼠标与键盘。

## 3. 世界观与系列结构

### 3.1 世界观

不可能仪器馆保存六台无法由普通物理定律解释的仪器。每台仪器都在输出错误结果，玩家需要通过观察、实验和推理完成校准。

统一叙事元素：

- 玩家身份：第 13 任校准员；
- 引导角色：只通过打字纸条交流的馆长；
- 关卡称呼：校准记录；
- 提示称呼：实验干预；
- 通关称呼：仪器稳定；
- 无限模式称呼：持续观测；
- 六台仪器修复后解锁总档案页与系列结局。

### 3.2 六款游戏总览

| 编号 | 游戏 | 核心新奇点 | 主要能力 | 预计单局 |
|---|---|---|---|---|
| 13-A | Shadow Cartographer / 影子制图仪 | 不移动目标，只移动光和遮挡物，用影子绘制路线 | 空间想象、光路推理 | 5–8 分钟 |
| 13-B | Möbius Mailroom / 莫比乌斯邮局 | 棋盘有正反两面，越过边界会翻面并改变方向 | 拓扑、路径规划 | 6–12 分钟 |

## 4. 游戏详细设计

### 4.1 13-A：Shadow Cartographer / 影子制图仪

#### 核心玩法

棋盘由光源、可旋转遮挡物、感光路径和目标印记组成。玩家不能直接绘制路线，而是旋转光源或遮挡片，让投影阴影覆盖指定感光格，同时保持禁区被照亮。

与普通光线反射游戏不同，本游戏计算的是遮挡形成的**阴影区域**，目标是用“没有光”的部分作画。

#### 玩家操作

- 拖动圆形轨道改变光源角度；
- 点击遮挡片旋转 45°；
- 长按单个感光格查看当前由哪个物体遮挡；
- 使用一次实验干预，显示某个遮挡物的影响区域。

#### 固定关卡

- 关卡 1–2：单光源、单遮挡物；
- 关卡 3–4：两个遮挡物重叠生成组合阴影；
- 关卡 5–6：加入必须保持照明的禁阴影格；
- 关卡 7–8：双光源，一个物体产生两组投影。

#### 无限生成

1. 随机生成合法光源与遮挡物参数；
2. 随机执行一组目标操作得到最终阴影；
3. 将该阴影作为目标；
4. 打乱仪器状态；
5. 使用状态搜索确认至少存在一个解，并计算最少操作数。

#### 完成条件

- 目标感光格全部处于阴影；
- 禁区全部保持照明；
- 连续稳定 600ms 后判定成功，避免拖动途中误判。

### 4.2 13-B：Möbius Mailroom / 莫比乌斯邮局

#### 核心玩法

玩家在一条首尾相连但带有一次翻转的带状地图上投递包裹。棋盘同时存在正面和背面；邮车越过特定边界后会翻到另一面，左右方向随之反转。

玩家不能控制邮车每一步，只能提前放置少量路标。启动后邮车会自动运行，玩家观察失败轨迹并调整路标。

#### 玩家操作

- 在空格放置左转、右转、直行或翻面路标；
- 切换查看棋盘正面/背面；
- 启动、暂停和逐步执行模拟；
- 回放最近一次失败路线。

#### 固定关卡

- 关卡 1–2：普通双面带，教学翻面；
- 关卡 3–4：正反面共享同一路标但效果镜像；
- 关卡 5–6：按指定顺序投递多个包裹；
- 关卡 7–9：限制路标数量并加入单向门。

#### 无限生成

- 从一条随机合法投递路径反向生成地图；
- 仅保留影响路径选择的墙体与路标位；
- 用模拟器验证不会陷入无限循环；
- 计算最少路标数并据此划分难度。

#### 完成条件

- 所有包裹按目标顺序送达；
- 邮车最终到达出口；
- 没有重复进入相同的“格子＋面＋方向＋载货状态”。

### 4.3 13-C：Echo Orchard / 回声果园

#### 核心玩法

果园会播放一段由颜色、位置和音高组成的“种子序列”。玩家不直接重复它；每轮果园会应用一种隐藏变换，例如倒序、循环位移、颜色取反、删除重复项或把前半段镜像到后半段。玩家需要输入**变换后的下一轮序列**。

#### 玩家操作

- 观看/聆听种子序列；
- 点击树冠节点输入预测序列；
- 可拖动调整已输入节点顺序；
- 请求实验干预后，可重播上一轮但降低评分。

#### 固定关卡

- 关卡 1–2：倒序和循环位移；
- 关卡 3–4：颜色映射与位置映射；
- 关卡 5–6：删除、复制或镜像子序列；
- 关卡 7–8：两个变换按固定次序组合。

#### 无限生成

- 从经过白名单审核的变换算子库中抽取 1–3 个算子；
- 生成不会产生歧义的种子序列；
- 比较候选规则输出，若多个规则得到相同结果则重新生成；
- 序列长度控制在 3–9 项。

#### 无障碍模式

- 所有音高同时用形状和垂直位置表达；
- 允许关闭声音；
- 动画播放速度支持 0.75×、1×、1.5×。

### 4.4 13-D：Gravity Grammar / 重力语法机

#### 核心玩法

单词卡不仅组成句子，还直接定义场景的物理规则。例如：

- `RED IS HEAVY`：所有红色物体向下施加两倍重力；
- `MOON PULLS LEFT`：月亮图块向左吸引相邻词；
- `NOT`：反转下一条规则；
- 标点符号决定规则作用范围。

玩家通过重新排列有限的词卡，让目标物体抵达出口，同时句子必须保持语法有效。

#### 玩家操作

- 拖动词卡改变句子；
- 点击运行，观察物理模拟；
- 逐帧执行并查看当前生效规则；
- 撤销到任意历史排列。

#### 固定关卡

- 关卡 1–2：`IS HEAVY`、`PULLS LEFT`；
- 关卡 3–4：颜色/形状作为主语；
- 关卡 5–6：`NOT` 与标点作用域；
- 关卡 7–10：两条规则竞争，要求构造稳定终态。

#### 无限生成

- 先从有效语法树生成一套规则；
- 模拟得到可达终态；
- 移除或打乱部分词卡形成谜题；
- 使用有限深度排列搜索验证存在解；
- 过滤可通过无意义重复运行完成的关卡。

#### 边界

首版只使用受控词表和离散格子物理，不实现自然语言自由输入或连续刚体物理。

### 4.5 13-E：Rule Fossil / 规则化石台

#### 核心玩法

仪器展示两组远古标本：“会发光”和“不会发光”。每个标本由形状、颜色、数量、纹理、朝向和相邻关系构成。玩家通过制造新标本并询问仪器是否接受，逐步推断隐藏规则，最后从规则卡中提交答案。

它不是普通找规律选择题：玩家可以主动设计实验，用最少查询次数排除假设。

#### 玩家操作

- 在标本台组合属性生成测试样本；
- 提交样本获得接受/拒绝反馈；
- 在假设板上排除候选规则；
- 最终提交规则或直接提交一个能证明规则的反例。

#### 规则示例

- “恰好两个蓝色图形”；
- “所有三角形都位于圆形左侧”；
- “存在一个与自身颜色相同的相邻标本”；
- “红色数量为偶数，但总数量为奇数”。

#### 无限生成

- 从规则语法树生成目标规则；
- 生成至少 3 个正例与 3 个负例；
- 枚举同难度候选规则，确保初始样本不能直接唯一确定答案；
- 验证存在最多 N 次主动查询即可区分目标规则的策略；
- 难度由属性数量、逻辑连接符和最小查询数共同决定。

### 4.6 13-F：Clockwork Alibi / 发条不在场证明

#### 核心玩法

玩家需要重建一组事件的时间线，但某些证词会随时间线变化而变化。例如：“钟响前我还没见到蓝钥匙”只有在钟响位置确定后才有意义；移动“停电”事件会隐藏其后的摄像记录。

玩家拖动事件卡时，证词、可见线索和时间约束会实时更新。目标不是找固定排列，而是找到一个让所有可见证据同时成立的稳定时间线。

#### 玩家操作

- 拖动事件卡调整顺序；
- 锁定已确认事件；
- 点击证词高亮它依赖的事件；
- 切换“当前证据”和“上一版证据”比较变化。

#### 固定关卡

- 关卡 1–2：单纯前后约束；
- 关卡 3–4：条件证词；
- 关卡 5–6：某事件会隐藏或显现线索；
- 关卡 7–9：循环依赖，但存在唯一稳定排列。

#### 无限生成

- 先生成一条完整合法时间线；
- 从合法时间线派生直接约束和条件约束；
- 随机隐藏部分约束；
- 使用约束求解器枚举解，要求只有一个稳定解；
- 若调整任何单张卡都不会产生即时反馈，则降低该关卡评分或重新生成。

## 5. 用户故事

### US-001：进入仪器馆总览

**描述：** 作为玩家，我希望看到六台仪器的修复状态，以便选择下一款游戏并理解系列目标。

**验收标准：**

- [ ] 总览展示六台仪器、编号、名称、玩法简介和修复状态。
- [ ] 未完成、已完成、已精通三种状态视觉明确。
- [ ] 可从首页游戏架进入总览或直接进入单款游戏。
- [ ] 键盘可聚焦并进入任意已开放仪器。
- [ ] TypeScript 和 ESLint 检查通过。
- [ ] 使用 in-app browser 验证桌面与移动端布局。

### US-002：完成固定校准关卡

**描述：** 作为新玩家，我希望通过逐步教学理解仪器规则，而不需要阅读长篇说明。

**验收标准：**

- [ ] 每款游戏至少包含 6 个固定关卡。
- [ ] 首关只引入一个核心动作。
- [ ] 新规则在首次出现时使用可跳过的上下文提示。
- [ ] 关卡完成条件由纯逻辑引擎判定。
- [ ] 刷新页面后保留已解锁关卡与最佳成绩。
- [ ] 使用 in-app browser 完成每款游戏的首关。

### US-003：游玩持续观测模式

**描述：** 作为已完成教学的玩家，我希望获得持续生成的新谜题。

**验收标准：**

- [ ] 完成每款最后一个固定关卡后解锁无限模式。
- [ ] 相同游戏 ID、难度和种子生成完全相同的关卡。
- [ ] 每个生成关卡在展示前通过可解性验证。
- [ ] 生成失败时安全重试，不向玩家展示坏状态。
- [ ] 生成过程在主流设备上不阻塞界面超过 100ms；较重搜索使用 Web Worker。
- [ ] 每个生成器至少包含 100 个不同种子的自动验证测试。

### US-004：使用实验干预

**描述：** 作为遇到困难的玩家，我希望获得与当前局面相关的提示，而不是直接看到答案。

**验收标准：**

- [ ] 每款游戏至少提供两级提示。
- [ ] 一级提示指出相关区域或规则；二级提示给出下一步建议。
- [ ] 提示始终基于当前状态计算。
- [ ] 使用提示会影响星级或得分，但不会阻止通关。
- [ ] 不存在提示后无解或提示进入局部死路的情况。

### US-005：跨游戏修复进度

**描述：** 作为系列玩家，我希望六款游戏共同推进仪器馆修复进度。

**验收标准：**

- [ ] 每台仪器记录固定关卡完成数、最佳评级和无限模式纪录。
- [ ] 完成一台仪器后在总览点亮对应展柜。
- [ ] 六台全部完成后显示系列结局档案。
- [ ] 进度存储带版本号并支持迁移。
- [ ] 存储不可用时仍可正常游玩当前会话。

### US-006：每日种子分享

**描述：** 作为玩家，我希望朋友能挑战完全相同的生成谜题。

**验收标准：**

- [ ] 每款游戏根据本地日期生成每日种子。
- [ ] 分享链接包含游戏 ID、模式、难度和种子。
- [ ] 打开链接后得到相同关卡，不包含答案或玩家状态。
- [ ] 结果页可复制由符号组成的非剧透成绩摘要。
- [ ] 分享 URL 输入经过严格验证。

### US-007：无障碍与多输入支持

**描述：** 作为使用键盘、触控或辅助技术的玩家，我希望完整操作所有游戏。

**验收标准：**

- [ ] 所有核心操作均支持键盘和触控。
- [ ] 不以颜色或声音作为唯一信息载体。
- [ ] 动画遵守 `prefers-reduced-motion`。
- [ ] 状态变化通过合适的 ARIA live region 播报。
- [ ] 点击目标最小尺寸为 44×44 CSS 像素。
- [ ] 使用 in-app browser 和键盘完成每款首关。

## 6. 功能需求

- **FR-1：** 系统必须提供六个独立公开路由和一个仪器馆总览路由。
- **FR-2：** 每款游戏必须将规则引擎、关卡数据、生成器和 React 展示组件分离。
- **FR-3：** 任何随机行为必须使用可注入、可复现的种子随机数生成器。
- **FR-4：** 每个程序生成器必须返回关卡、验证结果、难度评分和参考解。
- **FR-5：** UI 不得直接读取参考解；参考解只用于生成验证与提示计算。
- **FR-6：** 固定关卡必须以只读配置存储，并在测试中批量验证可解性。
- **FR-7：** 每款游戏必须支持重置、撤销、两级提示和结果结算。
- **FR-8：** 共享会话层必须记录用时、操作数、提示次数、撤销次数和完成状态。
- **FR-9：** 共享进度层必须使用带版本号的 `localStorage` schema，并捕获存储异常。
- **FR-10：** 无限模式必须支持至少简单、标准、困难三个难度档。
- **FR-11：** 每日挑战必须由日期和游戏 ID 派生种子，不能依赖服务器状态。
- **FR-12：** 所有关卡必须能够在中途安全退出；固定关卡恢复可列入第二阶段，无限局不要求恢复。
- **FR-13：** 结果页必须显示成绩、评级、是否使用提示和可复制分享摘要。
- **FR-14：** 首页必须将六款新游戏纳入已有分类筛选和可玩数量统计。
- **FR-15：** Sitemap 和每款游戏 Metadata 必须同步更新。

### 7.2 生成器统一契约

```ts
interface GeneratedPuzzle<TState, TAction, TSolution> {
  seed: string
  difficulty: 'easy' | 'standard' | 'hard'
  initialState: TState
  referenceSolution: TSolution
  estimatedComplexity: number
  validate(action: TAction, state: TState): ValidationResult
}
```

每个生成器还需实现：

- `generate(seed, difficulty)`；
- `isSolved(state)`；
- `solve(state)`；
- `getHint(state, level)`；
- `serialize(state)` 与 `deserialize(payload)`；
- `validatePuzzle(puzzle)`。

### 7.3 性能策略

- 简单穷举在主线程执行，但单次预算不超过 8ms；
- 约束求解、状态图搜索和批量生成放入 Web Worker；
- 生成器设置最大搜索节点数与重试次数；
- 关卡动画只改变 `transform` 和 `opacity`；
- 声音资源延迟加载，并允许全局静音。

### 7.4 测试策略

- 每个纯引擎覆盖状态变化、非法操作、胜利条件和撤销；
- 每个固定关卡自动运行参考解；
- 每个生成器对三个难度各验证至少 100 个种子；
- 对序列化数据执行损坏、旧版本和超范围输入测试；
- React 测试覆盖首关教学、提示、失败恢复和结算；
- 浏览器测试覆盖每款首关、移动端视口和键盘路径。

## 8. 设计考虑

### 8.1 共同视觉语言

- 总体风格：19 世纪科学仪器 × 不可能几何 × 现代信息显示；
- 共用黄铜铭牌、档案编号、校准刻度和馆长纸条；
- 每台仪器拥有一个主材质和强调色，而不是仅替换背景渐变；
- 结果动画表现为仪器机械结构恢复稳定。

### 8.2 独立视觉身份

- 影子制图仪：乳白感光板、墨黑投影、可拖动黄铜光源；
- 莫比乌斯邮局：双面纸带、邮戳、翻面时的空间折叠；
- 回声果园：夜色树冠、发光果实、声音传播波纹；
- 重力语法机：铅字排版、悬挂词块、物理方向箭头；
- 规则化石台：玻璃标本柜、分类标签、实验记录卡；
- 发条不在场证明：机械时间轴、证词纸条、因果齿轮。

## 9. 非目标

- 首版不提供实时多人对战或排行榜后端。
- 首版不要求用户登录或云端同步。
- 不使用大语言模型动态生成谜题或判断自然语言答案。
- 不实现用户自定义关卡编辑器。
- 不加入付费货币、体力限制或强制广告。
- 不为新游戏复制六套相同的会话状态与结果页代码。
- 不将六款游戏简化成同一套四选一题库换皮。

## 10. 分阶段实施建议

### 阶段一：共享基础设施

- 种子随机数、生成器契约、进度 schema；
- 仪器馆总览、共享 HUD、提示和结果组件；
- 每日种子与分享链接解析。

### 阶段二：低风险机制验证

- Echo Orchard；
- Rule Fossil；
- Clockwork Alibi。

这三款主要依赖离散状态，可先验证共享引擎、生成器和 UI 框架。

### 阶段三：空间模拟

- Shadow Cartographer；
- Möbius Mailroom。

需要额外的几何计算、轨迹回放和状态搜索。

### 阶段四：组合规则系统

- Gravity Grammar；
- 系列结局、全量浏览器验证和性能优化。

Gravity Grammar 的语法树与模拟组合复杂度最高，建议最后实现。

## 11. 成功指标

- 新玩家首关无提示完成率不低于 85%。
- 六款游戏首关平均理解时间低于 60 秒。
- 完成任意一款固定关卡后进入无限模式的玩家比例不低于 35%。
- 无限生成失败率低于 0.1%，不可解关卡为 0。
- 移动端单次交互响应低于 100ms。
- 六款游戏核心引擎测试覆盖率不低于 85%。
- 内部试玩中，至少 4/6 款被评价为“没玩过类似机制”。

## 12. 风险与缓解措施

| 风险 | 影响 | 缓解方案 |
|---|---|---|
| 新奇规则难以理解 | 玩家首关流失 | 用可操作教学取代说明页；首关只引入一个动作 |
| 无限生成出现无解局 | 严重破坏信任 | 所有关卡先生成参考解，再反向构造题面并运行求解器 |
| 六款同时开发导致质量分散 | 视觉和测试不一致 | 先完成共享契约，再按阶段逐款验收，不并行复制代码 |
| 搜索算法阻塞 UI | 移动端卡顿 | Web Worker、节点预算、生成重试和预生成缓存 |
| Gravity Grammar 组合爆炸 | 延期 | 首版限制词表、句法模板、格子尺寸和搜索深度 |
| 声音玩法影响听障用户 | 无法完成 Echo Orchard | 音高必须同时映射形状、位置和颜色 |
